🔴 Critical Finding: Guardrail Bypass in Resolve Endpoint POST /exceptions/{id}/resolve → ExceptionService.resolve_exception()

The resolve endpoint records an outcome and sets guardrail_decision: "AUTO" without calling GuardrailEngine.evaluate() from app/services/guardrail_engine.py. The real guardrail engine exists and is used by the LangGraph agent (app/agent/guardrail_node.py), but the REST API resolve path bypasses it.

Impact: Any client can resolve an exception with an arbitrary amount (up to ₹100,000) without guardrail validation.
Fix required: The resolve_exception() method must invoke GuardrailEngine before recording the outcome.
# Current (UNSAFE) flow: POST /exceptions/{id}/resolve → ExceptionService.resolve_exception() → guardrail_decision = "AUTO" ← hardcoded, no engine call → OutcomeService.record_outcome() → Response # Required (SAFE) flow: POST /exceptions/{id}/resolve → ExceptionService.resolve_exception() → GuardrailEngine.evaluate(exception, resolution) → if REJECTED → return 403 + reasons → if AUTO → OutcomeService.record_outcome() → Response
