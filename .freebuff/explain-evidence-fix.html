Root Cause

DATA ACCESS MISMATCH

Both services use the same FinancialDataAdapter, but access data through different methods:

✗ ExplainService (BROKEN)

# Called search_records() — returns WRAPPED results
records = adapter.search_records(limit=100)

# Results look like:
# {"type": "payment", "data": {payment_id: ..., amount: ...}}

# But code reads at wrapper level:
rec.get("exception_id")  # → undefined
rec.get("record_type")   # → undefined

✓ IntelligenceService (CORRECT)

# Uses direct adapter methods
case = adapter.get_case(exception_id)
payment_id = case.get("payment_id", "")
payment = adapter.get_payment(payment_id)
settlements = adapter.get_settlements_for_payment(payment_id)

Why search_records() failed: It returns results as {"type": "payment", "data": {...}} — a wrapper dict. But _load_financial_context() read fields like rec.get("exception_id") at the wrapper level (doesn't exist), so zero matches were found.

The Fix

✓ 1 FILE CHANGED

File: backend/app/api/explain.py — _load_financial_context() 

# BEFORE — used search_records() which returns wrapped results
def _load_financial_context(self, exception_id):
    records = adapter.search_records(limit=100)  # BROKEN
    for rec in records:
        if rec.get("exception_id") == exception_id:  # WRONG
            rec_type = rec.get("record_type", ...)   # WRONG

# AFTER — uses the same direct methods as IntelligenceService.get_evidence()
def _load_financial_context(self, exception_id):
    case = adapter.get_case(exception_id)
    if case is None: return context
    payment_id = case.get("payment_id", "")
    payment = adapter.get_payment(payment_id)
    if payment: context["payments"].append(payment)
    context["settlements"] = adapter.get_settlements_for_payment(payment_id)
    context["refunds"] = adapter.get_refunds_for_payment(payment_id)
    context["fees"] = adapter.get_fees_for_payment(payment_id)
    context["adjustments"] = adapter.get_adjustments_for_payment(payment_id)
